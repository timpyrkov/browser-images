Great question! The “**Detenido**” (“Stopped”) status you see for “Secuencia de comandos en segundo plano” (“Background script sequence”) in Firefox’s about:debugging is **expected behavior for Manifest V3 extensions**—and it’s a big change from how background scripts worked in Manifest V2.

---

## **What does “Detenido” mean?**

- In **Manifest V2**, background scripts were persistent: they ran all the time, so you could use timers, alarms, and listen for events continuously.
- In **Manifest V3**, background scripts are replaced by **service workers**. These are **not persistent**:  
  - They start up when needed (e.g., on an event, message, or alarm).
  - They are **stopped (“Detenido”) by Firefox when idle** to save resources.
  - When an event occurs (like an alarm or message), the service worker is restarted.

**So, “Detenido” just means the service worker is currently not running. It will be started again when needed.**

---

## **Is this a problem for timer-based add-ons?**

- **Not necessarily!**  
  - If you use the `alarms` API (e.g., `chrome.alarms.create`), Firefox/Chrome will wake up your service worker when the alarm fires—even if it’s currently “stopped.”
  - You should NOT rely on `setTimeout` or `setInterval` in the background script, as these will not work when the service worker is stopped.
  - You MUST use the `alarms` API for scheduled/background tasks.

---

## **How to do timer-based work in Manifest V3?**

1. **Use the `alarms` API**:
    ```js
    // In your background.js (service worker)
    chrome.alarms.create('backupTabs', { periodInMinutes: 60 }); // every hour

    chrome.alarms.onAlarm.addListener((alarm) => {
      if (alarm.name === 'backupTabs') {
        // Do your backup work here
      }
    });
    ```
2. **Do NOT use setInterval/setTimeout for long-running background tasks.**

---

## **References & More Info**

- [MDN: Background Service Workers (Manifest V3)](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest_v3#background_service_workers)
- [MDN: alarms API](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/alarms)
- [Chrome Extension Docs: Migrating to Service Workers](https://developer.chrome.com/docs/extensions/mv3/migrating_to_service_workers/)

---

## **Summary Table**

| Manifest Version | Background Script | Persistent? | Can use setInterval? | Can use alarms API? | “Detenido”/Stopped? |
|------------------|------------------|-------------|---------------------|---------------------|---------------------|
| V2               | Yes              | Yes         | Yes                 | Yes                 | No                  |
| V3               | Service Worker   | No          | No                  | Yes                 | Yes (expected)      |

---

## **TL;DR**

- “Detenido” is normal for Manifest V3 extensions.
- Use the `alarms` API for scheduled/timer tasks.
- Your extension will be woken up when the alarm fires, even if it’s “stopped.”
- Don’t use setInterval/setTimeout for background timers in V3.
